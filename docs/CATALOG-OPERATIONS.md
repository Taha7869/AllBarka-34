# Merchant catalog operations

The `products` Firestore collection is authoritative for fixed prices, custom price-per-100g, wholesale price, availability, and billing weights. Existing full legacy Product documents are validated and adopted on read without changing their prices. Canonical schema version 1 has a single `variants` array; the API derives `prices` for legacy components. Descriptive storefront content remains the reviewed source metadata. Never store cost, margin, supplier details, credentials, or staff notes in this public collection. Staff identity and prior pricing are stored in the private `catalogAudits` collection.

The public `/api/catalog` uses an ETag and a 15-second server cache. Active visible pages poll every 30 seconds and refresh on focus (maximum normal propagation 45 seconds). Product/detail/search/comparison/saved-cart/hamper views use the same runtime adapter. Open bags update available current prices; unavailable selections remain in the bag for review. Quotes read fresh records. Final order pricing reads the selected records in the order transaction, so concurrent catalog edits retry pricing. Saved receipts retain final prices, variant IDs, and catalog revisions; idempotent replay returns the earlier receipt before catalog reads.

Authenticated administrators use Catalog → Prices & availability. Save requires both a numeric revision and a content fingerprint. A Console edit changes the fingerprint even when its operator forgot to increment revision. Reload after conflicts. Fixed variant price and custom rate are independent. Invalid/missing records are unavailable instead of borrowing a compiled purchase price. Box fees in the custom hamper builder retain the existing approved source-defined fees; product contents use live prices.

## Reconcile before migration

Run `node --import tsx scripts/migrate-catalog.ts --dry-run`. This is read-only and prints IDs/actions and difference flags, never environment values. Check all 89 IDs and review live-vs-source differences with the owner. Runtime adoption already supports valid legacy records, so schema migration is optional.

Before any live writes, export a Firestore backup using the provider's backup/export facility and retain the existing release artifact. `--create-missing` creates only absent records with an exists=false precondition. It never overwrites existing records. `--adopt-legacy` converts valid existing records while preserving their actual live pricing and merchandising metadata; it deletes obsolete duplicate price aliases and writes one private audit per product. It aborts a product when its pricing changed since the plan. These write modes require an explicit operator action and are never run automatically at server startup or build.

## Rollback and incident handling

For a wrong merchant price, use the audited previous pricing in the admin editor and save a new revision; do not rewrite old orders or lower revisions. For a release rollback, retain schema version 1 compatible server code because old source-only releases ignore Firestore pricing. A full database rollback requires an operator-reviewed provider backup restore into a separate database, reconciliation, and controlled switch; never blindly overwrite an active order database. Missing/invalid product IDs are available in the server-only catalog snapshot `invalidProductIds` for readiness/alerts; public output contains unavailable products only. Direct Console edits require a named operator and provider audit logging; application actor attribution is guaranteed only for admin API changes.
