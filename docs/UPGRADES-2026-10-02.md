10. Download a text shopping summary, clearly distinguished from a confirmed order receipt.
11. Recover checkout details from this browser session; drafts expire after seven days, clear after accepted orders, and have an explicit reset action.
12. An optional five-address book with save/use/delete and clear local-device privacy wording.
13. Birthday, thanks and celebration message presets inside the gift-card controls, in all three languages.
14. Automatic authoritative server price/delivery quote, stale-response protection, bounded request timing and explicit retry.
15. Coupon application confirmed by the server. Removed browser-only fictional coupon effects; ALLBARKA10 follows the existing pricing contract.
16. Offline status and order-submit protection; reconnecting refreshes the quote.
17. Keyboard / shortcut to the visible home/shop search, disabled while typing or while a modal is open.

## Administration upgrade

- Rebuilt `/admin/orders` as a dedicated responsive workspace with overview, orders and catalogue navigation. Ivory surfaces, an emerald operations rail, readable status badges and restrained gold details follow the existing design system. Dark mode, 44px controls, mobile order cards and English/Urdu/Arabic are included.
- Overview uses actual stored order totals and filtered status counts. New-order, packing, transit and pending bank-payment queues lead to matching groups. Cancelled orders are excluded from monetary metrics; refunded records remain part of stored order value but are excluded from paid/unpaid totals. These figures are bookkeeping, not a revenue report.
- Order filters combine search, status, payment state, payment method and all/today/7-day/30-day ranges. Pakistan time determines the current calendar day. Customer search terms and loaded records stay in memory; no customer records are written to localStorage.
- Order details show customer contact/address, requested delivery date/slot, instructions, items, stored price breakdown and gift message. Details have a focus trap, Escape dismissal, background inertness and focus restoration.
- Status changes require a reason, current status and current order revision. Atomic transactions reject conflicting sessions, including an order that changed away from and back to its original status. Notes/status/payment share monotonically advancing revisions.
- Added private internal notes (1–1,000 characters; 100 per order including legacy notes), with actor/time audit entries and transaction rollback on audit failure. Unsubmitted drafts survive saving the other form.
- Payment controls record verified payment/correction states with reasons, current payment state and revision checks. They do not charge a card, initiate a bank transfer or execute a refund. Existing pricing, coupons, shipping and loyalty rules are preserved.
- CSV exports cover matching orders within the disclosed scan limit, rather than the current page. Unicode and multiline fields are preserved; spreadsheet formula inputs are neutralized. Exports happen only after the operator clicks the export control.
- Added per-order and page-selection packing previews and print sheets. Packing sheets include quantities, delivery/gift instructions and payment/total, with private admin notes excluded.
- Catalogue operations show canonical products, photo/portion/gallery counts, current prices, multilingual search and product links. An explicit image audit deduplicates local assets, caps requests, runs four workers, times out, supports cancellation and flags non-image HTML responses.
- Administrator access depends on strict verified Firebase custom claims. API responses omit guest claim secrets; reads use no-store. Admin pages have robots exclusions and noindex metadata/headers. A workspace link appears in the lounge only for verified admin claims.
- Admin UI, styles and its full translation dictionary load with the lazy route. Storefront footer/floating shopping overlays are suppressed on admin pages; the shared storefront header and homepage remain intact.
- Bounded network/token/body requests, cancellation, explicit retries and honest unavailable states replace indefinite loading and misleading empty ledgers when the database is absent.
