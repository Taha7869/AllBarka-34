## Corrected architecture

1. Website: explicit microphone tap, live 0:45 countdown, manual stop/cancel and graceful 45,000ms auto-stop. Decode and downmix/resample to 16,000Hz mono PCM16 WAV; primary path sends one request, then displays editable text. No automatic chat/search submission or order placement.
2. A canonical 45s WAV is `44 + 45 * 16000 * 2 = 1,440,044` bytes; 60s is `1,920,044` bytes. Both fit the existing `2 * 1024 * 1024` server byte ceiling. Target a 60-second server PCM ceiling for defensive capture overrun support, distinct from the 45-second UI timer. Update both WAV and provider-result duration checks together. Server validation remains strict for invalid, oversized or over-duration external requests.
3. Website defensive overrun: cap resampling output to at most 960,000 samples BEFORE allocating OfflineAudioContext output, then clamp the rendered samples. If input exceeds 60s, explicitly tell the user the end was excluded and ask them to record the remainder. This is bounded recovery, not a promise to preserve an arbitrarily long recording. `decodeAudioData` still decodes the captured container; keep the raw byte guard before decode.
4. Raw capture guard: proposed 4MiB budget. MediaRecorder may deliver a large final event; inspect actual codec/event behavior on phones. On overflow stop recording and release tracks. Do not byte-slice WebM/MP4 to pretend it is a valid audio file; preserve a decodable recording within bounded resources or show an honest recovery message.
5. Silence-aware chunking is optional, not required for a 45s file. If implemented, use a reusable bounded loop, not exactly two parts: at <=24s per chunk, 45s needs two and 60s needs at least three. For two non-overlapping 45s parts the split must be within 21–24s. Search low-RMS windows only within legal bounds; lowest energy is not proof of silence or an intact word boundary. If overlap is used, include it in the duration limit and reconcile duplicate boundary words without deleting legitimate repetitions, weights or quantities.
6. Each upload has its own timeout/cancellation lifecycle. Existing server timeout is 20s; use a larger client request deadline such as 25s, plus a separately bounded preparation/whole-operation budget when needed. Clear timers on stop/cancel/unmount/account change. Cancel the complete operation between chunks, prevent stale callbacks/results, and release all mic tracks even on permission races and recorder errors. Do not start chunk 2 with chunk 1's expired timer.
7. If chunking is later used, preserve completed text when another part fails. Retry only the failed part with bounded retries; handle 429 `Retry-After` without retry storms. Silence-only parts must not discard earlier speech. Show partial status honestly. Keep combined transcript and existing 1,000-character client/server input contracts consistent; preserve overlong text for correction instead of silently cutting an order quantity or rejecting all completed parts.
8. Stop speech output immediately on drawer/modal close (including an exit animation), microphone start, text/language change and relevant unmount. Preserve existing cancellation and cross-control behavior; do not recreate existing paths without evidence.
9. If metadata WAV support is added, scan RIFF subchunks safely, respect odd-byte padding, bound declared lengths, find valid `fmt ` and `data`, enforce PCM/mono/16kHz/16-bit/blockAlign/byteRate and calculate duration/silence from actual data bytes. Reject malformed, truncated, ambiguous duplicate or unsupported chunks with the existing safe error contract. Current code uses `VOICE_INVALID_AUDIO`, not `VOICE_INVALID_WAV`; do not introduce untranslated/mismatched codes casually.

## External quota facts and limits of the claim

Official documentation checked in this conversation on 5 November 2026:

- [Groq rate limits](https://console.groq.com/docs/rate-limits): published Whisper rows show 20 RPM, 2,000 RPD, 7,200 audio seconds/hour and 28,800/day. Limits apply at organization level, not per customer; confirm actual account limits in the console. Do not budget a guaranteed combined 16 hours by adding two model rows or bypass limits with model rotation.
- [Speech to text](https://console.groq.com/docs/speech-to-text): free upload limit 25MB; 16kHz mono preparation supported; larger files can use chunking. The 2MiB application ceiling is deliberately smaller. Requests below 10s have a documented 10s minimum billed length; do not infer that paid billing semantics prove free-tier accounting.
- Keep the private `GROQ_API_KEY`, allowlisted model and existing free-tier acknowledgement gate. No paid fallback or billing change. Website and WhatsApp requests using the same organization/model compete for its capacity; budget audio seconds as well as request count and retries.
- “Zero failure” and “100% transcription” are not acceptance criteria. Permissions, codec failures, noise, networks and quota can fail. Require bounded recovery and honest user-visible partial results. Vocabulary prompts guide spelling, not guaranteed Roman Urdu transliteration or factual order extraction; test real spoken product/amount examples before calling recognition verified.
