## Email and Google accounts

- Removed phone/SMS/reCAPTCHA authentication and its former OTP allowance endpoint. All account entry points use the same email and Google dialog.
- Added email sign-in, account creation with password confirmation, and email password-reset requests. Passwords go directly to Firebase Auth and are never saved in browser storage.
- Added Continue with Google using Firebase GoogleAuthProvider and an explicit popup started from the click gesture. It shares verified profile/session/guest-order recovery with email. Blocked or cancelled popups, account conflicts and configuration errors have translated feedback. The user's supplied Firebase console screenshot shows Email/Password and Google enabled, with Phone disabled. Production authorised domains and actual web configuration still need checking. The implementation follows [Firebase Google sign-in documentation](https://firebase.google.com/docs/auth/web/google-signin); it does not start an unconfigured redirect workflow.
- Contact and delivery telephone fields still serve their existing purposes.
- Profile creation writes only fields permitted by the existing Firestore rules. User ID and email are derived from authenticated Firebase identity; client writes cannot set roles, loyalty balances or membership permissions.
- Optional profile/session requests do not turn successful authentication into a failed login. Guest-order recovery keys clear only after a confirmed server claim.
- Explicit Bearer credentials take priority over old session cookies. Invalid explicit credentials cannot silently grant access through another account's cookie.
